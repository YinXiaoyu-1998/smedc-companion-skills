# 优先导出评价 Excel

采集时读取本参考。业务范围、门店映射、起草、九列审阅表及发布授权仍以 [SKILL.md](../SKILL.md) 为准。这里的“全量”是当前门店、渠道及筛选下的全部分页，不是所有门店、全部时间或必然包含已回复。企业及真实门店映射由本次任务提供，不写入技能。

## 生成并识别本次下载任务

1. 在评价管理的全局门店选择器确认原始全名及可用 POI，再选美团/点评渠道；按本次要求设置回复状态、星级、来源、用户及精确日期。等加载完成，记录筛选、页面总数及当前时间；已有可见下载任务时记录其标识作对照。已确认结果为零时直接按主技能报告，不因加载中的零条跳过。
2. 点击“下载数据”一次。它可能打开/复用新的下载列表标签，也可能提示稍后到下载列表查看；先检查标签和提示，再使用页面现有“下载列表”，不重复提交导出。用当前工具文档支持的浏览器能力处理弹出页；内置浏览器缺少所需能力时，按主技能说明原因后复用可用的登录会话，不迁移凭据。
3. 在下载列表查找本次新增任务，综合任务标识、生成时间、渠道、日期范围及可见筛选判断；必要时点“刷新状态”查询该任务。等待须有界，持续无法取得文件时保存任务信息并使用页面兜底，续跑先查旧任务。最新第一项只是候选，不能无条件下载。列表可能只显示“全部类型”，也可能不显示门店及回复筛选，因此它不能单独证明范围。并发同名任务无法唯一关联时，先核对任务详情或下载后的文件；仍有歧义则保留待核对并使用页面兜底，不猜归属、不连续创建任务。
4. 确认该任务显示“下载成功”后点该行“下载”，捕获下载结果或系统保存窗口。下载事件超时不代表没有保存窗口：先检查原生保存框及实际文件，再决定恢复；不能因超时连续点击下载。原名保存至本次本地目录，避免覆盖旧文件，记录任务到路径的对应。若页面明确显示生成失败，可在排除已有成功任务后重试一次；有界恢复仍失败时改用页面兜底并记录原因。
5. 读取文件后核对原始门店、渠道、日期、回复筛选及数据行数与本次上下文。列表任务没有足够元数据时，更需依赖这一步；不以文件名相同证明属于当前门店。结果集变化或数量不一致时核对生成时间、标识和变化原因，不能直接宣布全量成功。文件显示的过期提示是实际下载期限，生成后及时下载。

## 可靠读取文件

- 原始导出保留不改。先看工作表、表头和样本，再按列名映射，不固定列序或只读当前页面的前十条；数据量大时流式遍历。
- 平台文件可能把 worksheet dimension 错写为 `A1`，但实际 XML 有完整数据。使用 openpyxl 的只读模式时，在遍历前对目标工作表调用 `reset_dimensions()`；其他读取器使用等价的实际数据范围检测。不能把 `max_row == 1`、空预览或缺少默认样式当作空表。

```python
from openpyxl import load_workbook

wb = load_workbook(path, read_only=True, data_only=True)
try:
    ws = wb[sheet_name]  # 先确认该表包含评价表头
    ws.reset_dimensions()  # 忽略可能错误的 A1 范围，按实际单元格流式读取
    rows = ws.iter_rows(values_only=True)
    headers = next(rows)
    # 按 headers 查找字段索引，再逐行处理 rows；不要先按 max_row 截断。
finally:
    wb.close()
```

- 缺少必要列、重复表头、损坏文件或不能确认字段语义时，保留文件并报告，不按错位列猜值。读取完整数据后对账；只跳过全部单元格确为空的行，不因正文为空丢掉纯评分评价。
- ID、昵称、正文及回复按文本处理；客户正文按主技能的字符处理规则保留换行、可识别表情及 `[米饭]` 等平台图标文字，仅省略无法可靠识别的 emoji／图形部分并记非异常说明。不为追求与旧页面纯文本相同而删除可识别标记，也不因个别不可识别图形额外补采。后续审阅表文本不能被当作公式执行。

## 字段归一化

当前表头如下；后续格式变化时重新核对实际语义。

| 导出列 | 用途 |
| --- | --- |
| 评价ID | 原始文本另存；`feedbackId = "feedback-" + 评价ID`，连字符必需，保存到本地记录及表格行映射，不给九列加列 |
| 用户昵称 | 客户名字，保留原显示文本；不合并同名客户 |
| 评价 | 客户原评价；空值/已确认系统无正文提示按主技能写真正空值 |
| 评分 | 总评分的有限数值，如 `4.5`；不保存标签、展示单位或数字字符串，不补小项或零值 |
| 门店 | 来源全名，用本次任务的映射确定标准门店；POI 使用切店上下文 |
| 评价时间 | 保留原始时间及实际精度，核验范围/时区后统一为 `YYYY-MM-DDTHH:mm:ss+08:00`；不得截去导出真实秒数 |
| 评价展示平台 | “美团”→“美团评价”，“点评”→“点评评价”；须与当前渠道一致 |
| 商家回应 | “是/否”是原始回复事实，不能只凭正文列或回复列是否为空推断 |
| 回应&盖楼内容 | 按下节拆分作者并提取全部商家回复 |

“评价来源”可能是“消费后评价”“打卡后评价”等类型，不能作为美团/点评渠道。省份、城市及写评用户身份可用于范围校验，但不能推断企业归属。

评价 ID 保留精确字符串，不先转浮点数、科学计数法或截断。若读取器得到数字，只在可证明整数值及精度完整时转十进制文本；ID 缺失、精度已丢失或身份冲突时保留原行并用页面核验，不编造 ID。去重键至少含来源门店/POI、渠道和 `feedbackId`；不同来源门店映射到相同标准名时仍保留各自记录。

## 评分归一化

先分离已确认的维度标签与值，再将每个值解析为有限数字。`4.5星`、`4 分`、`5心` 分别保存为 `4.5`、`4`、`5`；JSON 使用 `{"总评": 4.5, "口味": 4, "服务": 5}`，维度名称仍保留为键。原生数值无需附加单位，不能把布尔值当作评分，不能平均小项、补零、改变量纲或四舍五入来凑平台范围。

只接受完整匹配的单个数值与已知展示单位；`4.5/5`、`4–5星`、百分比或未知文字须核对，不能靠删除所有非数字字符强行转换。下面的标准库示例仅解析评分值，调用前已分离维度标签；新单位须先确认来源含义再扩展：

```python
import math
import re

def numeric_score(value):
    if isinstance(value, bool):
        raise ValueError("Boolean is not a score")
    if isinstance(value, (int, float)):
        number = float(value)
    elif isinstance(value, str):
        match = re.fullmatch(r"\s*([+-]?(?:\d+(?:\.\d+)?|\.\d+))\s*(?:星|分|心)?\s*", value)
        if not match:
            raise ValueError("Ambiguous score")
        number = float(match[1])
    else:
        raise ValueError("Missing or unsupported score")
    if not math.isfinite(number):
        raise ValueError("Non-finite score")
    return int(number) if number.is_integer() else number
```

九列审阅表第四列只存总评分的原生数字，小项留在本地结构化记录及后续获授权同步中；总分未确认则第四列为空并说明原因。不能把多维 JSON 或带单位的拼接文本放进这一单元格。清理仅针对评分值，不对客户正文、商家回复、维度名称或整个 JSON 文本全局删除“星”“分”“心”。

## 多段商家回复合为一条 string

“回应&盖楼内容”是线程容器，不能把整个单元格直接当商家回复。当前包装形如 `【2026-01-02 12:34:56】商家:第一段`；同一单元格可能包含多条回复及不同作者。

1. 按所有“时间＋作者”包装识别消息边界，再筛选明确标为“商家”的消息；不能只按商家头切分，否则会把下一位顾客的跟帖并进商家正文。遇到不能可靠识别的包装或作者，不能猜其归属。
2. 去掉各条的结构性时间、作者及消息间分隔符，保留商家正文、表情及段内换行。按文件原顺序连接：`merchantReply = "\n\n".join(merchant_parts)`。相同内容出现多次也全部保留，不去重、润色、截断或只留最后一条。最终保存 string，不保存数组的字符串表示；原始线程单元格另留本地追溯。
3. “商家回应＝是”且全部商家段已完整提取时，第三列填写该 string，状态为“已回复”，无论原评价是否有正文。“是”但回复缺失或解析不完整时，只读补查该评价；仍不完整则第三列留空，状态“已回复待核对”，不能生成替代稿。
4. “商家回应＝否”且没有相反回复证据时，按有无正文决定起草或留空；“否”却有商家消息、字段值未知或来源互相矛盾时标为“待核对”，核实前不起草或发布。

例如线程顺序为“商家：甲 → 顾客：追问 → 商家：乙”，最终商家回复为一条 string `甲\n\n乙`，不包含顾客追问；原始顺序和重复消息均保留。第三列已有回复仍按主技能排除新稿字数检查。

## 输出与续跑

导出文件读取完后，仍按主技能起草并生成独立九列审阅表，保留五种状态及数据行对账。`feedbackId`、原始文件/行号、下载任务、来源门店/POI、筛选、读取时间和审阅表行号保存在本地对应记录；不能只保存审阅表行号。

已确认的评价时间在本地规范记录、后续获授权同步和审阅表显示中统一使用北京时间 `YYYY-MM-DDTHH:mm:ss+08:00`。源文件的空格分隔日期只转换格式和已知时区，不改变实际时刻。Excel 原生日期单元格存北京时间墙钟值，显示格式固定为 `yyyy-mm-dd"T"hh:mm:ss"+08:00"`；原始精度另外记录，分钟来源补 `00` 仅为兼容规范表示，不表示平台实际秒数已确认。例如使用 openpyxl 写一个已确认的日期单元格：

```python
from datetime import datetime
from zoneinfo import ZoneInfo

confirmed = datetime.fromisoformat(reviewed_at)  # 规范字符串含 +08:00
cell.value = confirmed.astimezone(ZoneInfo("Asia/Shanghai")).replace(tzinfo=None)
cell.number_format = 'yyyy-mm-dd"T"hh:mm:ss"+08:00"'
```

格式比较前先按已知时区规范化；`2026-01-02 12:34:56` 与 `2026-01-02T12:34:56+08:00` 是同一时刻。规范化应幂等，不给已含秒及偏移的字符串再次拼接 `:00`、`Z` 或时区。分钟兼容值 `12:34:00` 与导出真实值 `12:34:56` 则是精度差异，不能只靠格式化认定二者相同或评价实际时间改变；按调用任务的存量身份核对规则处理，保留来源及依据，不自动回填历史。

导出可用且仅缺小项评分时视为可用采集，不额外翻页。其他问题优先只读补查对应评价，整个导出不可用才完整逐页采集。已成功采集的记录与兜底记录按来源身份对账，避免重复。

更精确的导出时间不授权改写历史记录或自动回填其他系统。后续任务若另行同步历史数据，须核对旧记录时间精度与稳定评价标识，避免仅因分钟/秒差异新增重复；同步由对应能力及其授权处理。本技能仍到交表结束，发布前仍按主技能重新核验网页目标及状态。
