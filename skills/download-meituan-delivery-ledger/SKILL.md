# 下载美团门店收货单

取得指定收货日期、门店范围内的完整原始配送收货单。每张收货单保留一个 XLSX，ZIP 仅作为批量下载的包装。

## 智能体与工具兼容性

本技能描述通用业务流程，可由能够读取技能说明、操作浏览器及检查本地文件的智能体执行。浏览器操作使用当前运行环境提供的工具；`cua_repl`、`tab.playwright`、`cua.getApp` 是下文已使用的具体接口示例，并非所有智能体都具备。其他环境应按自身工具文档完成等价的页面定位、下载捕获及文件保存；缺少相应能力时说明阻塞，不假定示例 API 可用。不同运行环境的下载行为需要单独验证。

## 浏览器选择

- 在 Codex 中，优先使用内置 Chromium 浏览器（`iab`）：先查找该浏览器内的美团标签，没有则在 `iab` 新开页面。使用 `cua_repl` 时，按当前文档调用 `cua.createBrowserTab("iab", "https://pos.meituan.com/web/operation/main#/", { visible: true })`。其他智能体遵循用户或运行环境的浏览器偏好。
- 内置浏览器未登录时，请用户在内置页面自行登录，再继续本次任务。不要仅因本机 Chrome 已登录就转去控制它，也不假定两个浏览器共享登录状态；不读取或迁移 Cookie、凭据。
- 仅在用户明确指定本机浏览器/其标签，或已确认内置浏览器缺少完成任务所需的能力、必须使用现有本机会话或扩展时，才回退到 Chrome/Edge 等本机浏览器。回退前简要说明具体原因；普通等待、尚未登录或一次下载超时本身不足以触发回退。
- 查询、导出、下载清单和保存都留在选定浏览器中。内置浏览器按自身工具文档处理下载或保存文件；下文 Chrome 原生保存框示例只在实际使用本机 Chrome 时适用，不能据此打开本机主浏览器。

## 参数与边界

- 日期：使用用户指定的起止日期，包含两端；单日任务起止相同。未提供且上下文不能确定时询问，不照搬演示日期。用户说“昨天”时，按本次运行的北京时间取前一自然日，并在续跑时保持该日期。
- 日期口径固定为 **收货日期**。若用户要求订单日期等其他口径，明确记录变更，不能把两种口径混用。
- 单据状态默认 **已收货**；用户指定的其他状态优先。检查默认的“待收货”已取消，避免混入未收货单据。
- 门店/机构范围使用用户指定范围。未指定时检查并报告当前页面范围；若无法确认其满足请求，先询问。不硬编码企业名称、门店名称或机构数量，也不把“已选择若干机构”当作全部门店的证明。
- 保存目录默认当前用户 `~/Downloads`，不可用时使用 `~/Desktop`；用户指定目录优先。解析实际主目录，不写死用户名或演示目录。
- 每批 ZIP 默认名为 `meituan_delivery_ledger_YYYYMMDD_YYYYMMDD_partNN.zip`，从 `part01` 开始，解压至同名目录。日期来自本次筛选，批次编号按实际导出顺序增加。压缩包内保留美团原始文件名和文件内容，不合并成一份日期汇总 Excel。
- 同名文件先核验日期、范围、收货单集合及完整性；一致可复用，不一致使用新的批次/运行子目录，禁止静默覆盖。
- 本技能负责下载。只有用户要求上传时才转交 `smedc-mcp`；演示下载不代表授权上传。
- 需要登录或验证时，请用户在美团页面自行完成，保留本次日期及进度。不索取、记录或导出密码、验证码、Cookie、签名下载地址。

## 进入与查询

1. 按“浏览器选择”规则选定浏览器，用当前智能体的浏览器工具查找其中的 `美团管家` 标签；有则复用，没有则在同一浏览器打开 `https://pos.meituan.com/web/operation/main#/`。检查登录状态；确认未登录时，请用户在该页面自行登录，完成后继续本次日期的任务，不索取登录凭据。
2. 入口为 `https://pos.meituan.com/web/operation/main#/`。打开 **供应链 → 门店收货单**，根据当前可见导航找到入口。确认页面包含“批量导出单据明细”和收货单号等列；不要误入“采购收货单”。
3. 将“日期”口径从可能默认的“订单日期”切换为 **收货日期**，设置开始、结束日期。展开筛选，核对 **已收货**、门店/机构及其他条件；不能让页面遗留的单号、供货机构或仓库筛选悄悄缩小范围。
4. 点 **查询**，重新读取实际日期、状态、门店范围及结果总数，作为本次对账基准。零结果时报告该范围无单据，不创建假数据文件。
5. 若提供 **200 条/页**，选用并等待列表刷新。记录总条数、页数和当前页；不要把界面只渲染的部分行数当成整页条数。

## 逐页导出

1. 从第一页开始。每批先点选择栏的 **清空**（若有已选项），确认“已选 0”，再通过表头复选框选中当前页。
2. 核对“已选”数量等于当前页应有条数，且仅包含该批未导出的单据。记录批次、页码、选择数及可获得的收货单号，用于防漏、防重复。
3. 使用下节的下载处理，点击 **批量导出单据明细**。不使用“批量导出单据列表”：后者不能替代每单完整明细。不要触发批量收货、撤销收货、返货等业务写操作。
4. 等待生成并检查原生保存窗口。演示中的首批生成约需 40 秒；短暂没有窗口不等于失败。分段检查生成状态和保存窗口，不反复点击导出。
5. 将 ZIP 保存为本批目标名称，验证实际存在、非空和压缩包完整后再处理下一页。如界面提供异步下载任务，按当前界面的入口、申请时间与状态定位本批，完成后下载；不要套用其他报表的下载清单 URL。
6. **完成一批后清空选择，再翻下一页，再选当前页。** 美团会跨页保留勾选，直接选第二页可能把已导出的第一页一起加入。
7. 导出所有页，累计核对数量。结果集在过程中变化时重新核对单号集合和缺失批次，不能仅凭批次数宣称完整。

### 跨页选择失败的恢复

录制观察到：200 单一批成功；跨页累积选中 249 单后，页面两次提示“批量导出单据明细失败”；清空选择后单独选第二页 49 单成功。这支持逐页导出策略，**不证明平台存在固定 200 单硬上限**。

遇到失败时先检查“已选”数量及跨页残留，保留已验证批次，清空后仅选择缺失的当前页。若单页仍失败，记录页面错误，按页面明确限制或缩小批次处理，停止无变化的重复点击。不可将未下载批次算作完成。

## 下载事件与 ERR_BLOCKED_BY_CLIENT 处理

先遵循“浏览器选择”规则；在内置浏览器中使用其文档支持的下载捕获与保存能力。下面的 Chrome 接口示例仅在实际使用相应浏览器和工具时适用，不构成切换到本机 Chrome 的理由。每次点击可能直接下载文件的 **导出、批量导出单据明细或下载** 前，先按当前工具文档注册下载等待，再点击当前快照中核实的按钮。不要把下载地址作为普通网页导航，也不要提取、打印或保存签名 URL。

以下示例针对提供 `cua_repl` / `tab.playwright` 接口的环境；仅在当前工具明确支持这些 API 时使用。其他工具按自身文档先准备下载捕获，再触发下载并保存文件（`tab`、`downloadIndex` 来自当前页面，不复用录制索引）：

```javascript
const pending = tab.playwright.waitForEvent("download", { timeoutMs: 10000 })
  .then(download => ({ download }))
  .catch(error => ({ error }));
await tab.click(downloadIndex);
const result = await pending;
```

1. 先在当前浏览器中检查下载结果；若工具直接返回下载文件或支持保存 API，按其文档保存至目标路径。出现系统 `Save` 保存对话框时，使用当前环境支持的窗口能力完成保存；只有实际使用本机 Chrome 时，才用 `cua.getApp("Google Chrome")` 或已绑定的 Chrome 原生 app 检查。保存框可能不出现在网页 AX/DOM 中；不要为了检查内置浏览器下载而打开本机 Chrome。
2. 区分等待超时与其他错误，不把所有异常都标为超时。超时可能是文件仍在生成或等待系统保存，不能单凭超时判定下载失败，也不要因此重复点击。错误只报告安全摘要，不输出可能带签名地址的原始错误对象。
3. 每次新的下载重新注册等待，等待时长小于当前工具的调用时限。生成较慢时分段检查页面状态及原生窗口；若页面提示异步下载任务，按本技能对应的入口定位本次任务，完成后下载。
4. 以本地文件实际存在、非空、日期/范围正确及 XLSX/ZIP 完整性作为完成依据；事件返回或保存框出现本身不代表成功。同名文件先核验，一致可复用，不静默覆盖。
5. 仍出现 `ERR_BLOCKED_BY_CLIENT` 时，先检查原生保存窗口、本地文件与导出状态，再保留目标日期、已完成导出项/批次和待续事项，报告具体阻塞。不要关闭安全防护、不断重新导出或重复下载已验证文件。按当前控件名称和状态操作，不固定坐标或行号。

验证范围：以下结果来自此前使用上述接口的 Chrome 环境，不代表已验证内置浏览器或所有智能体。2026-09-30，同一已完成菜品报表的普通自动点击重现 `ERR_BLOCKED_BY_CLIENT`；先注册下载等待再点击则弹出保存框。菜品、营业各自动保存一份，与人工下载原文件的 SHA-256 完全一致。收货单目前只有人工录制及本地文件验证，自动回放尚未验证。以上支持采用该下载处理顺序，未核实浏览器工具内部根因，不能据此断言是美团反爬、扩展或代理导致。

## 本地验证与解压

1. 每个 ZIP 存在、非空，能被 ZIP 读取器打开，所有成员 CRC 检查通过；排除 HTML 错误页、未完成的下载临时文件。
2. 解压前检查成员路径：拒绝绝对路径、`..` 越界和符号链接，不覆盖现有文件；解压到该批独立目录。可用 Python `zipfile` 等文件工具完成本地检查与安全解压。
3. 枚举实际收货单 XLSX，忽略目录和 `__MACOSX` 等包装项；记录非预期文件，不把它们计作收货单。每份 XLSX 非空、ZIP 结构与 CRC 完整，并含 `[Content_Types].xml`、`xl/workbook.xml` 和工作表。
4. 只读检查每份单据的表头元数据：收货单号、门店/机构、**收货日期**，并确认有明细区域。日期与请求范围相符；不要从收货单号中的数字或订单/发货日期推断收货日期。Excel 日期按工作簿日期系统解析。
5. 以收货单号核对各批次唯一性；同号同内容记为重复，不重复计数；同号内容冲突保留两份并报告。唯一收货单数量应等于查询总数，且每批文件数与选择数一致。
6. 任何文件损坏、日期异常、缺失元数据或数量不符都报告为未完成/待核对，保留正确批次并仅补缺失部分。不能以“下载了 ZIP”代替完整性验证。
7. 输出日期口径、起止日期、状态、门店范围、ZIP 和解压目录的绝对路径、每批及去重后数量、完整性与对账结果。不输出表格行级业务数据。

## 后续 SMEDC 上传

用户明确要求后，读取并执行 `smedc-mcp` 当前官方规则，先认证和确认 admin 权限，再为上传读取文件。使用 `dataset=delivery_ledger`，按每张收货单上传原始 XLSX；不直接上传 ZIP，不合并、不改列、不去除表头。该数据集由服务提取单据元数据，不套用 dishes/business 的日期分区参数；导入成功状态以当前官方工具与 skill 的规则为准。仅下载完成时不要报告 SMEDC 导入成功。
