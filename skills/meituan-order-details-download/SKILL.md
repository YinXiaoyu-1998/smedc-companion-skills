# 美团店内订单明细下载

取得指定日期口径、时间范围、门店及订单状态的原始 `.xlsx`，完成本地保存并验证。使用 Computer Use（浏览器及必要的原生窗口操作）完成美团界面流程；若当前环境有覆盖此报表的专用工具，优先使用等价的查询、导出和保存能力。

## 参数与边界

- **时间范围**：采用本次请求的开始、结束日期，包含两端；单日起止相同。未提供且上下文无法确定时询问，不照搬录制日期，也不默认下载昨天或整月。相对日期按本次运行的北京时间解析，续跑保持原范围。
- **日期口径**：页面提供 `下单时间`、`结账时间`、`营业日期`，按请求明确选择；请求及上下文不能确定时询问。录制的下载清单只显示“查询时间范围”，不足以证明选中了哪种口径。营业日期可能跨自然日，不能因下单或结账时间越过零点就判断异常。
- **订单状态**：默认明确选择 `已结账`；未收到用户本次明确要求时，不因准备上传或凑齐字段而自行切到 `全部订单`。用户明确指定其他集合/状态时按请求执行，并重新核验该集合的来源列。导出前读取实际选中项，不依赖页面遗留值或上次任务。
- **门店范围**：采用用户指定门店、机构或品牌范围，展开机构树核对实际子门店及排除项。未指定时读取并报告当前范围；不能确认它满足请求时询问。勾选父机构后可逐项取消门店，不能将父机构名称或“已选若干项”当作全量证明。企业、机构、门店名称及数量不硬编码。
- **其他筛选**：完整下载时核对订单来源、经营模式、结账方式、关键字、收银员、菜品及金额等筛选没有意外缩小范围。保留用户明确要求的条件；字段设置未要求修改时沿用当前配置，并说明导出配置或列完整性无法确认的情况。
- **保存**：用户指定目录及文件名优先；默认当前用户 `~/Downloads`，不可用时用 `~/Desktop`，解析实际主目录。默认名 `meituan_order_details_<日期口径>_<订单状态>_YYYYMMDD_YYYYMMDD.xlsx`；有时分筛选时补充时间，多门店范围文件用范围标识或独立子目录区分。日期取本次查询范围，不能从美团原始文件名的导出时间推断。保留原始字节及 `.xlsx`；同名文件先核对，一致可复用，不一致另存，禁止静默覆盖。
- **任务范围**：只下载原文件，不改列、不转换格式、不生成分析。用户明确要求上传时再转交 `smedc-mcp` 当前规则；本报表不能因含营业或菜品字段就归为 `business`、`dishes` 或 `delivery_ledger`，须先确认官方支持的数据集。
- 登录、验证码由用户在美团页面自行完成，保留筛选及进度。不索取或记录密码、验证码、Cookie、签名下载 URL；不把行级订单、会员信息及录制中的私有内容写进聊天或技能。

## 浏览器与工具

本技能可由能操作浏览器、原生保存窗口及检查本地文件的智能体执行。`cua_repl`、`tab.playwright`、`cua.getApp` 仅为特定环境的接口示例，调用前读取当前工具文档；其他环境使用等价能力，缺少能力时说明具体阻塞。

在 Codex 中优先使用内置浏览器 `iab`：复用其中的美团标签，没有则新开 `https://pos.meituan.com/web/operation/main#/`。未登录时由用户在该页面登录，不读取或迁移 Cookie。仅用户明确指定 Chrome/Edge 或其标签，或确认内置浏览器缺少必要能力、必须使用已有本机会话或扩展时，才回退到本机浏览器，并简要说明原因。尚未登录、普通等待或一次超时不足以触发回退。

查询、导出、下载清单及保存都在选定浏览器完成。录制使用 Chrome，不意味着后续必须使用 Chrome。原生窗口操作只绑定本次浏览器所属的保存框；不要为检查内置浏览器下载而打开本机 Chrome。

## 查询与导出

1. 打开 **报表中心 → 营业报表 → 店内订单明细**，确认页面标题和订单明细列。导航不可用时，可在选定浏览器尝试录制中观察到的直达页 `https://pos.meituan.com/web/report/orderList#/rms-report/orderList`，再核对页面。不要误入“自助营业取数”或“全渠道订单明细”。
2. 先按“长范围优先按月导出”规划当前段，再选定日期口径，用日期控件设置该段起止范围；历史日期可切换年月，按当前年月和目标日期定位，不重放录制中的翻月次数。日期含时间控件时核对起止时分；整日查询核对覆盖当日完整范围。
3. 打开门店选择树，选择本次范围并核对子门店及排除项。选择 `已结账` 或请求状态，核对其他筛选。菜单切换、重置或导航可能触发刷新，最终重新读取日期口径、起止值、门店和状态。
4. **每次修改搜索参数后，都先点查询，等待结果刷新，再点导出**。包括改动日期口径、起止时间、门店、订单状态或其他筛选，以及切换到下一个分段；即使页面看似自动刷新，也执行本步。查询后再改任何参数，须重新查询，不能直接导出。记录这次查询实际生效的筛选和可见总条数（如提供）；零结果如实报告，不创建假数据。页面可能只显示一页或部分行，这不是总量。
5. 确认结果对应最后一次参数改动，按“下载捕获、系统保存框与恢复”先准备捕获，再点 **导出** 一次。录制中该按钮导出查询结果并生成异步任务，不需要逐页勾选；不要套用收货单逐页批量导出的流程。当前页面若另有“当前页/全部”等选项，按请求确认选择，不将当前页冒充全量。提示数据量过大、不支持导出时，执行下节分段流程；不对原范围反复点击导出。
6. 可能直接出现保存框或下载文件，也可能提示 **前往下载清单**。直接下载进入保存与验证；异步任务从提示打开 **下载清单记录**。入口缺失时在同一浏览器打开 `https://pos.meituan.com/web/fe.rms-portal/rms-report.html#/rms-report/promiseDownload`。
7. 用 `店内订单明细-已结账 (查询时间范围：<开始时间>-<结束时间>)`、本次申请时间及状态定位任务。其他订单状态使用清单实际名称。清单混有营业、菜品报表及相同日期的历史任务，不能仅点第一条“下载”。门店和日期口径若未在清单显示，依靠本次查询与申请身份关联，不声称清单已证明这些条件。
8. **导出中**时保留该任务，适度刷新清单，不重复提交导出。页面的一般等待时间只是提示，不是完成保证；记录任务后分段等待，避免密集刷新。**导出完成**后按“下载捕获、系统保存框与恢复”准备捕获，再点该行 **下载**。明确因数据量过大失败时按下节切分；其他失败、过期或任务无法辨认时保留筛选与申请信息，报告待续事项，不删除任务或无变化地重试。

## 长范围优先按月导出

1. 长时间范围（如半年、一年或多年）的历史批量下载，默认先按自然月规划，再逐月从美团导出原始 XLSX；不等导出超量或后续 SMEDC 入库超时后才切分。用户明确指定其他分段方式时优先遵循。补充录制观察到“数据超过20万条”的提示，这是当次页面线索，以运行时实际限制为准。普通生成等待或下载超时按下载恢复规则处理，不单凭超时认定数据超量。
2. 保留原请求完整范围，月初、月末按实际日历计算，首尾不足整月的部分截到请求边界。整日范围各段包含两端，下一段从前段结束日期次日开始，保证无遗漏、无重叠。有时分条件时按控件实际精度衔接并核对端点，不擅自扩大为整日；页面跨度限制更短时继续缩小查询段。
3. 每段保持相同的日期口径、门店范围、订单状态和其他请求条件，只调整该段起止时间；每次调整后严格执行 **查询 → 等待刷新并核对 → 导出**，再走对应任务的下载、保存与验证。单月仍超量时，只把该月继续拆为更短的周段或日段；最小可用时间跨度仍超限时，保留已完成部分并报告剩余范围，不擅自排除门店、订单或更改口径。
4. 维护分段进度：实际起止范围、查询条数（如有）、导出任务申请信息、目标路径和状态，区分待查询、导出中、待下载、已验证、查询无数据与失败。每份文件用该段实际起止日期命名，保留独立的美团原件，不在本地拆写大工作簿或合并月度文件。已存在同条件任务先恢复；已验证段复用，新增子段只覆盖尚缺范围。缩短范围后的新分段与原参数下载重试分开记录。
5. 全部子段验证完成后，核对其范围并集恰好覆盖原请求；无数据段须有对应查询结果佐证。仅部分月份完成时报告已完成与剩余段，不以一份文件下载成功宣称半年数据已齐。

用户已要求上传时，按 `smedc-mcp` 当前数据集契约逐份提交完整月度原件，每份使用自己的实际日期范围、稳定幂等键和导入状态；下载完成不代表入库成功。已有大范围导入任务时，先确认旧任务已终止再用子段恢复，只补未完成范围。此策略降低单次工作量，不保证每月均不会超时；上传数据集及订单状态完整性仍须按核心 Skill 核对，不因这里的下载默认值而放宽。

当前 `in_store_orders` 要求完整门店日的全部订单状态，`已结账` 子集即使列齐全也不能作为该完整快照上传。用户只要求已结账时，保持该筛选，下载验证后保留原件并报告“已下载，上传待契约兼容”；不能自行扩大到全部订单、沿用旧 `settled_orders` 名称或补列后重传。只有当前官方契约明确支持所请求的快照范围时，才按其数据集与参数上传。

## 下载捕获、系统保存框与恢复

此环节参照 `download-meituan-business-data`、`download-meituan-dish-sales` 的处理方式，关键规则在此完整给出，无需加载其他报表流程。

每次点击可能直接下载文件的 **导出** 或 **下载** 前，先按当前工具文档注册下载等待，再点击当前快照核实的控件。不要把签名下载地址当普通网页导航，或提取、打印、保存签名 URL。

提供以下 API 的环境可使用此模式；`tab` 及 `downloadIndex` 来自本次页面。用 `cua_repl.js` 时外层调用设置 **`timeout_ms: 60000`**，下载事件连续等待 **45 秒**，不要用多个独立的 10 秒等待拼接：

```javascript
const pending = tab.playwright.waitForEvent("download", { timeoutMs: 45000 })
  .then(download => ({ download }))
  .catch(error => ({ error }));
await tab.click(downloadIndex);
const result = await pending;
```

按实际结果继续：

- **系统保存框**：点“下载”不等于已保存。检查选定浏览器的原生窗口；保存框可能不出现在网页 DOM/AX 中，也可能归属于系统 Open and Save Panel Service。实际使用 Chrome 时可通过 `cua.getApp("Google Chrome")` 或已绑定的 Chrome app 检查。录制可见 `保存` / `save-panel`、`位置：`、文件名栏 `saveAsNameTextField` 和 `保存` / `OKButton`；它们是定位线索，索引必须重新读取。选择目标目录、核对文件名及 `.xlsx`，点 **保存**，再检查文件。需要精确路径时使用当前系统支持的“前往文件夹”控件或快捷键进入绝对目录。覆盖提示出现时先核验已有文件，不直接确认替换。
- **自动下载或工具返回文件**：按当前工具文档等待传输完成并保存至目标位置。浏览器实际目录可能与目标不同，先确定本次文件，必要时以不覆盖方式移至目标，保留字节；文件存在后仍执行下节验证。
- **等待超时或 `ERR_BLOCKED_BY_CLIENT`**：先检查当前浏览器下载记录、可访问的保存框、默认目录、目标路径及本次任务。超时可能仍在生成、传输或等待保存，不代表失败。区分其他错误，只报告安全摘要，不打印可能含签名 URL 的原始错误对象。
- **恢复上限**：确认没有文件、进行中的生成/下载或待保存框后，允许对同一文件自动重试一次。已有已完成任务时只重试该项下载；确无可恢复任务时才重新导出。每次重试仍先注册下载等待，并记录次数，续跑不重置。前次结果无法确认或重试仍失败时，保留任务和进度并报告阻塞。不得关闭安全防护或重复下载已验证文件。

## 完成验证

1. 核实实际文件绝对路径、非零大小和传输完成，排除 `.crdownload`、HTML 错误页或只有保存框却未保存的情况。
2. 只读验证 XLSX：ZIP 可打开、成员 CRC 通过，包含 `[Content_Types].xml`、`xl/workbook.xml` 及工作表。读取表头/元数据确认是订单明细，检查订单号、门店及本次日期口径对应的列；已结账原件还须核对“结账时间”列存在。缺列与列内空值分别报告，不用下单时间代替结账时间，不自行补列或填造时间，文件内容保持原样。
3. 如工作簿有查询条件，核对与请求一致；可读取的日期、门店及状态列也应在本地核对，只报告汇总结果。日期按对应列及工作簿日期系统解析，不能拿另一日期列代替。页面提供总数时核对实际明细行数，排除标题、表头及合计行，不将多工作表重复或分页显示数当作全量证明。缺失证据或无法对账时如实说明，不宣称范围或数量已验证。
4. 分段任务逐份执行上述核验，并按“长范围优先按月导出”检查原范围覆盖。报告各文件绝对路径与实际分段日期、原请求范围、日期口径、订单状态、门店范围及文件/对账结果，明确无数据段和待续段。异步任务完成、下载事件返回和保存框出现都不能单独作为本地下载成功的依据。
