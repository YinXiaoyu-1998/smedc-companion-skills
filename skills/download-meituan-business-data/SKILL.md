# 下载美团营业数据

目标是按指定营业日期范围下载美团管家的原始营业数据 `.xlsx`，并核实日期与文件完整性。日期范围由本次请求确定，文件名中的两个日期分别对应开始日期和结束日期。

## 智能体与工具兼容性

本技能描述通用业务流程，可由能够读取技能说明、操作浏览器及检查本地文件的智能体执行。浏览器操作使用当前运行环境提供的工具；`cua_repl`、`tab.playwright`、`cua.getApp` 是下文已使用的具体接口示例，并非所有智能体都具备。其他环境应按自身工具文档完成等价的页面定位、下载捕获及文件保存；缺少相应能力时说明阻塞，不假定示例 API 可用。不同运行环境的下载行为需要单独验证。

## 输入与边界

- 优先采用用户指定的营业日期范围、查询方案、门店范围及保存目录。未指定日期时，按录制习惯取前一已结束营业日；若该日尚无数据，询问用户要等待还是换日期。未指定方案时选 `全量数据`。起止日期允许相同，表示只下载该日数据。
- 未指定保存目录时，默认保存到当前用户的 `~/Downloads`；下载目录不可用时使用 `~/Desktop`。将 `~` 解析为当前用户主目录，不硬编码用户名或企业项目目录。
- 未指定文件名时，默认使用 `meituan_business_YYYYMMDD_YYYYMMDD.xlsx`，两个日期分别替换为本次导出的开始日期和结束日期。用户明确指定的目录和文件名优先；遇到同名文件先核对，避免覆盖。
- 只下载原文件；上传 SMEDC 须有用户另行要求，并按 `smedc-mcp` 的权限和原文件上传规则执行。不要改列、转换格式或生成业务结论。
- 不记录或保存密码、验证码、Cookie、下载签名 URL，也不把行级营业数据贴入聊天。

## 操作

1. 用当前智能体的浏览器工具（例如 Computer Use 的 `cua_repl`）查找已打开的 `美团管家` 标签；有则复用。没有时，在 Chrome 新开 `https://pos.meituan.com/web/operation/main#/`，检查是否已登录。新页面也可能沿用已有登录会话；只有确认未登录时才暂停，请用户在网站页面自行登录，然后继续。
2. 打开 `报表中心` → `自助营业取数`。在 `常用查询` 中选择 `全量数据` 或用户指定的方案。
3. **选方案后再设日期**：方案可能将日期重置到历史区间。通过页面日期控件设置 `营业日期` 的开始和结束日期，可设成同一天。检查显示的日期、门店和 `退单状态` 等筛选符合请求；未要求调整时保留方案的维度和指标。
4. 点 `查询`，确认结果对应目标日期和方案，再点 `导出`。
5. 导出可能很快完成并直接打开系统保存对话框，也可能提示前往 `下载清单` 等待生成；两种情况都正常，按实际出现的界面继续。若直接出现保存对话框，就选择目标目录，按实际日期命名，保留 `.xlsx` 后保存。若需要进入下载清单，则从提示入口或报表中心打开 `下载清单记录`；找不到入口时，可在同一已登录的 Chrome 会话中打开下载清单直达页 `https://pos.meituan.com/web/fe.rms-portal/rms-report.html#/rms-report/promiseDownload`。找到本次 `营业分组表(营业日期【开始日期-结束日期】)`，确认申请时间和 `导出完成` 状态，再点该行的 `下载` 并保存。生成中不视为已下载。
6. 确认文件存在且非空，并用 `file` 或等价方式核实为 OOXML 工作簿；必要时检查 ZIP 完整性。向用户报告绝对路径、日期范围、查询方案和验证结果。

按页面标题、控件名称和下载清单行内容操作，不依赖录制时的坐标或行号。

## 下载事件与 ERR_BLOCKED_BY_CLIENT 处理

适用于智能体通过浏览器工具控制 Chrome 下载；其他浏览器按当前工具文档采用等价的下载处理。每次点击可能直接下载文件的 **导出、批量导出单据明细或下载** 前，先按当前工具文档注册下载等待，再点击当前快照中核实的按钮。不要把下载地址作为普通网页导航，也不要提取、打印或保存签名 URL。

以下示例针对提供 `cua_repl` / `tab.playwright` 接口的环境；仅在当前工具明确支持这些 API 时使用。其他工具按自身文档先准备下载捕获，再触发下载并保存文件（`tab`、`downloadIndex` 来自当前页面，不复用录制索引）：

```javascript
const pending = tab.playwright.waitForEvent("download", { timeoutMs: 10000 })
  .then(download => ({ download }))
  .catch(error => ({ error }));
await tab.click(downloadIndex);
const result = await pending;
```

1. 随即用当前工具支持的原生窗口能力检查系统 `Save` 保存对话框；在 `cua_repl` 环境可用 `cua.getApp("Google Chrome")` 或已绑定的 Chrome 原生 app。若工具直接返回下载文件或支持保存 API，按其文档保存至目标路径。保存框属于原生窗口，网页 AX/DOM 可能保持不变；出现后填写目标目录、文件名并完成保存。
2. 区分等待超时与其他错误，不把所有异常都标为超时。超时可能是文件仍在生成或等待系统保存，不能单凭超时判定下载失败，也不要因此重复点击。错误只报告安全摘要，不输出可能带签名地址的原始错误对象。
3. 每次新的下载重新注册等待，等待时长小于当前工具的调用时限。生成较慢时分段检查页面状态及原生窗口；若页面提示异步下载任务，按本技能对应的入口定位本次任务，完成后下载。
4. 以本地文件实际存在、非空、日期/范围正确及 XLSX/ZIP 完整性作为完成依据；事件返回或保存框出现本身不代表成功。同名文件先核验，一致可复用，不静默覆盖。
5. 仍出现 `ERR_BLOCKED_BY_CLIENT` 时，先检查原生保存窗口、本地文件与导出状态，再保留目标日期、已完成导出项/批次和待续事项，报告具体阻塞。不要关闭安全防护、不断重新导出或重复下载已验证文件。按当前控件名称和状态操作，不固定坐标或行号。

验证范围：以下结果来自此前使用上述接口的 Chrome 环境，不代表已验证所有智能体或浏览器。2026-09-30，同一已完成菜品报表的普通自动点击重现 `ERR_BLOCKED_BY_CLIENT`；先注册下载等待再点击则弹出保存框。菜品、营业各自动保存一份，与人工下载原文件的 SHA-256 完全一致。收货单目前只有人工录制及本地文件验证，自动回放尚未验证。以上支持采用该下载处理顺序，未核实浏览器工具内部根因，不能据此断言是美团反爬、扩展或代理导致。

## 后续 SMEDC 上传

用户已明确要求上传时（包括同一次请求中的下载并上传），读取并执行 `smedc-mcp` 当前官方规则，使用官方 MCP 工具继续；已有授权无需重复确认。

1. 调用 `smedc_auth_status`；未登录时调用 `smedc_login` 打开官方登录页，由用户自行登录。保留本次日期、路径与进度，登录后继续，不把待登录报告为已上传。不索取凭据。
2. 使用 `smedc_get_current_user` 确认 `admin` 角色后，再为上传读取文件；员工角色不得为上传读取、转换文件或调用上传工具。用 `list_structured_datasets` 确认数据集可用。
3. 默认以当前账号的 `organizationName` 作为 `enterpriseName`，结合原文件所属企业及 `describe_structured_dataset_coverage` 的现有 business/dishes 覆盖范围核对。企业名不一致或归属不确定时先请用户确认；无现有覆盖时不能声称已核对一致。不硬编码企业名或提供 organization ID。
4. 调用 `upload_structured_dataset`，使用 `dataset=business`、`file.encoding="path"` 和原始 XLSX 绝对路径，`startDate`、`endDate` 为实际导出范围的 `YYYYMMDD`（单日两者相同）。上传完整原文件，不拆分、改列或转换格式。使用与确切文件字节及上传元数据绑定的稳定 `idempotencyKey`；同一文件与元数据的获准重试复用原 key。未指定 `confidentialityLevel` 时省略，采用服务默认值。
5. 保存 `partitionImportJobId`，按 `smedc-mcp` 的分区轮询规则调用 `get_partition_import_status`；只有 **published** 才报告该份上传成功。处理中、失败或等待用户操作时如实报告状态、任务 ID 与待续事项，不用重复上传代替查询状态。仅下载完成时不报告 SMEDC 导入成功。
