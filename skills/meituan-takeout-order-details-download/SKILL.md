# 美团平台外卖订单明细下载

取得本次请求范围内的原始 `.xlsx`，完成本地保存与只读验证。使用 **Computer Use** 操作浏览器及必要的原生保存窗口；当前环境若有明确覆盖此报表的专用工具，优先使用其等价查询、导出和保存能力。读取当前工具文档后再调用，以下接口名只适用于提供相应能力的环境。

## 本次输入

- **时间范围**：使用用户要求的开始、结束日期，包含两端；单日起止相同。相对日期按本次北京时间解析，续跑保留原范围。请求及上下文无法确定时询问，不沿用录制月份或默认下载昨天。含时分的请求按控件实际精度设置；整日查询核对完整起止时间。
- **日期口径**：页面提供 `下单时间`、`接单时间`、`营业日期`，按请求选择并核实最终选中值。没有明确口径时询问；录制中点击过选项不能证明最终值。营业日期可能跨自然日，不能用下单时间代替它校验范围。
- **门店范围**：采用用户指定的门店、机构或品牌范围。展开机构树核对实际子门店及排除项，父机构名称和“已选若干个”不足以证明全量。未指定时读取并报告当前范围，无法确认满足请求时询问。企业、门店名称、数量均为输入，不硬编码。
- **订单集合与订单状态**：页面标签 `有效订单 / 全部订单 / 无效订单` 与筛选框 `订单状态` 分别核对。普通未限定请求默认标签 `有效订单`、状态筛选 `全部`，与录制可见配置一致，并在结果中说明；用户要求全部订单时明确切到 `全部订单` 标签，不能只把状态筛选设为全部。不要套用店内报表的“已结账”默认值。
- **来源及其他筛选**：无额外限制的请求将订单来源、订单形式、菜品分类/名称、退单标识等设为全部，清除遗留的订单尾号、取餐号、全渠道流水号、收餐人电话、备注、金额限制；`只看含退款订单` 不勾选。核对“更多筛选”中的收藏门店、首次下单等条件。保留用户明确要求的限制；“美团管家报表”不自动等于只选“美团外卖”来源。字段设置未要求修改时沿用当前配置，无法确认导出列完整性时说明。
- **保存位置**：用户指定路径优先；默认解析当前用户的 `~/Downloads`，不可用时用 `~/Desktop`。默认名 `meituan_takeout_order_details_<日期口径>_<订单集合>_YYYYMMDD_YYYYMMDD.xlsx`；有来源、状态、时分或多组门店限制时加入范围标识或用独立子目录区分。日期取实际查询区间，不取美团文件名中的导出时间。同名文件先核对：条件一致且已验证可复用，否则另存，禁止静默覆盖。

只下载并保留原始字节，不改列、不合并、不生成分析。用户另行要求上传时再读取 `smedc-mcp` 当前规则，先确认官方支持的数据集；不能因文件含营业或菜品字段就归类为 `business`、`dishes` 或 `delivery_ledger`。

登录和验证码由用户在美团页面自行完成；保留筛选及进度。不索取或记录密码、验证码、Cookie、签名下载地址，不把订单、电话等行级私有内容写入聊天或技能。

## 打开报表

在 Codex 中优先复用内置浏览器 `iab` 的美团标签，没有则新开 `https://pos.meituan.com/web/operation/main#/`。未登录时由用户在该页面登录，不迁移 Cookie。仅用户指定本机浏览器/标签，或确认内置浏览器缺少必要能力、必须使用既有本机会话或扩展时，才回退 Chrome/Edge，并简述原因；普通等待、未登录或一次超时不足以触发回退。

1. 打开 **报表中心 → 平台外卖订单明细**，以标题及门店、订单来源、外卖订单号、收银订单号等列确认报表。导航不可用时，在选定浏览器尝试录制观察到的直达页 `https://pos.meituan.com/web/report/orderListWM#/rms-report/orderListWM`，随后核对标题。不要混用店内或全渠道订单明细。
2. 先按“长范围优先按月导出”规划当前段，再按“本次输入”设置日期口径、该段起止范围、门店、订单集合、状态及其他筛选。历史月份按当前和目标年月定位，不重放录制中的点击次数。菜单切换、重置及导航后重新读取最终筛选。
3. **每次修改搜索参数或订单集合标签后，都先点“查询”，等待刷新完成并核对，再点“导出”**。查询后又改任何参数，必须重新查询。记录实际生效条件和可见总条数（如提供）；一页行数不是总数。零结果如实报告，不创建假数据。

## 导出与下载清单

1. 结果与最后一次查询条件一致后，先按下节准备下载捕获，再点 **导出** 一次。录制观察到同一报表既可直接下载，也可生成异步任务；不能固定只走其中一条路径。没有观察到逐页勾选要求；若当前页面出现“当前页/全部”选项，按请求选定，不将当前页当全量。
2. 直接出现保存框或下载事件时，进入“下载捕获与保存”。若提示 **前往下载清单**，打开 **下载清单记录**；入口不可用时在同一浏览器打开 `https://pos.meituan.com/web/fe.rms-portal/rms-report.html#/rms-report/promiseDownload`。
3. 用 `平台外卖订单明细 (查询时间范围：<开始时间>-<结束时间>)`、本次申请时间及状态定位任务，兼容页面实际日期格式。清单混有其他报表和同区间历史任务，不能直接点首个“下载”。清单未显示日期口径、门店、来源或订单集合时，用本次查询和申请身份关联；不能声称清单已证明这些条件。
4. **导出中**时保留原任务，分段等待后使用清单 **刷新**；避免反复提交或照搬录制中的密集刷新。页面“一般在20分钟后可下载”是提示，不是完成保证；保留期限以当前页面为准。
5. **导出完成**后，先准备下载捕获，再点该行 **下载**。单段明确超量时按下节继续缩小查询范围；其他失败、过期或任务无法辨认时，保留条件和申请信息并报告待续事项，不删除或无变化地重试。

## 下载捕获与保存

每次点击可能下载文件的 **导出** 或 **下载** 前，按当前工具文档先注册下载等待，再点击当前快照核实的控件。不要提取、打印或导航签名下载 URL。

在提供以下 API 的环境中，可沿用参考技能的等待模式；`tab` 和控件索引来自本次页面。使用 `cua_repl.js` 时外层设 **`timeout_ms: 60000`**，事件连续等待 **45 秒**，不拼接多个独立短等待：

```javascript
const pending = tab.playwright.waitForEvent("download", { timeoutMs: 45000 })
  .then(download => ({ download }))
  .catch(error => ({ error }));
await tab.click(downloadIndex);
const result = await pending;
```

按实际结果处理；原始错误可能包含签名 URL，只报告安全摘要：

- **系统保存框**：检查选定浏览器的原生窗口，必要时检查系统 Open and Save Panel Service。网页快照可能不含保存框。录制可见 `保存 / save-panel`、`位置： / where popup`、文件名 `saveAsNameTextField`、保存按钮 `OKButton`；这些是定位线索，索引重新读取。选择本次目标目录，核对 `.xlsx` 文件名，点 **保存**。精确目录通过系统“前往文件夹”控件或快捷键输入绝对路径。覆盖提示先核验已有文件。只检查本次浏览器所属窗口，不为内置浏览器下载另开本机 Chrome。
- **自动下载或工具文件**：按文档等待传输完成，确定本次文件的实际路径，必要时不覆盖地移至目标位置并保留字节，再验证。浏览器“完成”提示不替代文件检查。
- **超时或 `ERR_BLOCKED_BY_CLIENT`**：先检查当前浏览器下载记录、保存框、默认目录、目标路径及对应导出任务。超时可能仍在生成、传输或等待保存，不直接判定失败或超量。
- **恢复上限**：仅确认没有文件、进行中的生成/下载或待保存框后，允许同一文件自动重试一次。已有完成任务时只重试下载，确无可恢复任务时才重新导出；每次仍先捕获下载。记录次数，续跑不重置。结果不明或一次重试后仍失败，保留进度并报告阻塞；不关闭安全防护或重复下载已验证文件。

## 长范围优先按月导出

长时间范围（如半年、一年或多年）的历史批量下载，默认从一开始就按自然月规划，在美团逐月查询、导出独立原始 XLSX；不先尝试整年大文件，也不等导出超量或 SMEDC 入库超时后才切分。用户明确指定其他分段方式时优先遵循。单日和短区间保持请求范围，不照搬演示月份或硬编码行数上限。

1. 保留原始完整范围，首尾月份截到请求边界。例如 `2024-06-20 至 2025-06-19` 分为 `2024-06-20 至 06-30`、中间完整自然月、`2025-06-01 至 06-19`，共 13 段。整日段包含两端，下一段从前段结束日期次日开始；有时分条件时按控件精度衔接并核对端点，保证无缺口或重复。页面跨度限制更短时继续缩小查询段。
2. 各段只改起止范围，保持日期口径、门店、订单集合、状态、来源及其他条件。逐段执行 **修改范围 → 查询 → 等待并核对 → 导出 → 保存并验证**。单月仍超量时只继续拆该月，缩至周段或日段；最小可用跨度仍超限时报告剩余范围，不擅自排除门店或订单。
3. 记录每段实际范围、查询总数（如有）、申请身份、路径、状态及重试次数；区分导出中、待下载、已验证、无数据和失败。先恢复已有同条件任务，复用已验证文件。每份按该段实际日期命名并保留美团原始字节，不在本地拆写大工作簿或合并月度文件；新子段只覆盖尚缺范围。
4. 全部完成后核对分段范围并集恰好覆盖原请求；无数据段须有查询结果佐证。仅完成部分时分别报告已完成及待续范围。

用户已要求上传时，读取 `smedc-mcp` 的 `takeaway_orders` 当前数据集契约，确认服务及企业权限可用后逐份提交完整月度原件；每个门店日仍须包含全部平台、全部有效订单，不按平台、订单或小时拆分。每份使用自己的实际日期范围和稳定幂等键，保存独立导入任务，只有 `published` 才算该份入库成功。已有大范围导入任务时，先确认旧任务已终止再用子段恢复，保留已成功月份，只补未完成范围。

按月可降低单次导出和入库工作量；launcher 的网络 multipart 分块处理的是传输字节，不能替代这里的业务日期分段，也不能保证消除服务端入库超时。普通下载等待先按恢复规则处理，不单凭超时判定数据超量；单月仍有明确容量问题时才继续缩至周段或日段。
