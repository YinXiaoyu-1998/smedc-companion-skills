# 成本卡本地 CSV 分析

成本卡 launcher `0.10.0` 已发布并独立验证，当前安装 pin 为 0.10.0；安装仍按员工请求
和基础 `smedc-mcp` 的受控流程执行。使用成本卡前另行确认目标服务已上线、企业类别已配置
并且当前账号获准读取。静态 tools/list、包发布与安装本身都不能证明服务或租户就绪。
本指导不改变现有报表 runner、bundle schema、查询计划、诊断／周报／月报产出，
不新增利润报表或服务端分析。仅在员工要求关联成本卡或分析用料时读取。

1. 通过基础 Skill 核对当前账号及授权。`cost_cards` 是企业集团级类别，需 enabled、
   当前类别密级和明确 grant。配方“适用门店”是业务文字，不是读取权限；管理员可管理但
   不一定可读。来源原件另有读取权，原件归档不使有效卡消失。
2. 用 `query_structured_dataset(dataset="cost_cards", mode="detail")` 按目录找卡、翻页。
   可按企业、来源、SPU／SKU、菜名、规格、分类、售价等公开标量筛选，不能向服务端发送
   物品、配方、单位、门店明细筛选或聚合。售价筛选／输出是精确十进制字符串或 null，
   revision 是字符串。名称 contains 是字面子串，不做同义词或模糊身份推断。
   身份是组织＋企业＋来源＋SPU＋SKU，单个 SKU 或菜名不唯一。同名多规格、同 SKU 不同
   SPU 保留所有候选；关联销售时遵守 [名称关联优先级](dish_name_association.zh.md)，
   记录使用的销售名称列，不能任取一张卡或把两列同时连接而重复计算销售。
3. 选择准确的卡 ID 或目录条件，通过 `download_cost_cards` 下载。字段之间 AND、数组
   内 OR，显式 IDs 必须全部可读有效；没有日期／门店选择器。只消费 launcher 成功返回的
   本地文件与去链接 manifest，不把 CSV 正文、base64、签名 URL 装进上下文。
   每卡独立文件按卡 ID 命名，同名不覆盖；失败不当成空结果或部分成功。
4. 读取该次 manifest，按卡保留 `costCardId`、`revision`、`sourceDocumentId`、
   `importBatchId`、身份、schema、行数、字节和 checksum。来源 ID 只作溯源，不授予
   原件访问权。目录查询和下载是两次重新授权的当前读取，不承诺前次查询的历史版本。
   链接失效最多领取一次新清单，先清理旧轮全部输出，再整批重下；不混合两份清单。
5. 本地使用标准 CSV reader 按字符串读取 38 列：35 业务列＋3 源定位列
   `source_sheet_index`／`source_sheet_name`／`source_row_number`。它不是上传模板，
   更新应走 35 列原始档案。编码保留前导零，数字用 Decimal 精确运算，百分比是比例，
   空值不等于 0。业务 contentHash 与文件 checksum 含义不同；源行、门店文本排版变化
   可能改变文件字节，不代表业务更新。
6. 按卡／配方类型＋名称分组后，在本地筛选物品、单位、数量和适用门店。保留标准与
   例外原文、重复物品次数、零数量和源定位；`全局（标准配方）`／`特定（例外配方）`
   只是源文本示例，不硬编码成只有两类。保留门店文本并独立处理其集合，不改权限范围。
   不混单位相加、不从净料率或基准单位猜换算，不把物品名称硬关联到别的物品编码。
   不推断例外替换或叠加标准配方，不把重叠适用门店判成生命周期状态，不根据来源
   “是否配置／删除”清空或归档。多套配方成本分别展示，不生成唯一最终配方或整卡／
   最终门店成本。缺少换算或配方选择依据时保留原始可比较值与具体待核实项。
7. 将需要的结论和安全来源信息写入本次分析记录；使用 `try/finally`，在成功、失败、
   取消时删除仅本次 download 返回的临时目录。此本地分析不进入现有 runner 清理账本，
   不依赖其分区清理替你处理成本卡；不删除员工原件、其他下载或持久结论。

卡按完整内容更新、未上传卡不变；新上传可恢复归档卡，旧幂等请求不会恢复。发布摘要
只说明那次提交，changes 可截断但计数不截断，且需当前读取权；不从今天的目录回建。
替换 CSV 至少 24 小时后才可清理，宽限不提供历史访问。分析不得自行上传、归档、修改
类别授权、执行真实清理或回填；这些动作只在员工明确请求及基础 Skill 允许的范围执行。
